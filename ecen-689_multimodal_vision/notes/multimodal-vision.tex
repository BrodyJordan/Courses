\subsection{Neural networks -- the original linear classifier}
(Before) Linear score function: $f = Wx$.
(Now): 2-layer neural network: $f = W_2 \max(0, W_1 x)$.
where $x \in \R^D$, $W_1 \in \R^{H \times D}$, $W_2 \in \R^{C \times H}$.

ReLU still used commonly as activation function, good default choice for most problems.
Leaky ReLU has small weight on left side. \\

Forward processing is done at inference time. Backward processing is done at training time. \\

\subsubsection{Computing gradients}
$ s = f(x; W_1, W_2) = W_2 \max(0, W_1 x) $ nonlinear score function; \\

$ L_i = \sum_{j \neq y_i} \max(0, s_j - s_{y_i} + 1) $ hinge loss on predictions; \\

$ R(W) = \sum_{k} W_k ^2 $ regularization; \\

$ L = \frac{1}{N} \sum_i L_i + \lambda R(W) $ total loss: data loss + regularization

\subsubsection{Backpropagation in Neutral Networks}
$ f(x, y, z) = (x + y)z $ \\
$ q = x + y $ \\
$ f = qz $ \\
Then, by chain rule,
\[
    \frac{\partial f}{\partial x} = \frac{\partial f}{\partial q} \frac{\partial q}{\partial x} = z \cdot 1 = z
\]
\[
    \frac{\partial f}{\partial y} = \frac{\partial f}{\partial q} \frac{\partial q}{\partial y} = z \cdot 1 = z
\]
\[    \frac{\partial f}{\partial z} = \frac{\partial f}{\partial q} \frac{\partial q}{\partial z} = q \cdot 1 = x + y
\]

\subsection{Cameras and rays}
We need the mathematical mapping from (camera, pixel) $\to$ ray. Then we can abstract underlying problem as learing the function ray $\to$ color (the "plenoptic function").
\subsubsection{Coordinate frames + transforms: world-to-camera}
Extrinsics $(R,T)$ (rotation, translation) brings world coordinates to camera coordinates. Intrinsics $(K)$ bring camera coordinates to image coordinates. The reverse process is also possible for both of these steps. 
\subsubsection{Neural volumetric rendering}
Continuous, differentiable meaning.
\subsubsection{Surface vs. volume rendering}
We want to know how rays interact with scene. Surface rendering -- loop over geometry, check for ray intersection. Volume rendering -- loop over ray points, query geometry. \\ 

\noindent Volume rendering: rendering model for ray $r(t) = o + td$:
\[
  C \approx \sum_{i=1}^N T_i \alpha_i c_i
\]
How much light is blocked along ray: 
\[
  T_i = \prod_{j=1}^{i-1}(1-\alpha_j)
\]
How much light is contributed by ray segment 
\[
  \alpha_i = 1 - e^{-\sigma_i \delta t_i}
\]
\section{Rendering: projecting 3D to 2D}
Neural radiance field is a subset of neural rendering. Typically have 3 stages. Let the pixles find what features they need.
\subsection{Neural radiance field (NeRF)}
\[
  \arg\min_{V} \sum_{i} \norm{\mathcal{R}(V; R^{(i)}, t^{(i)}, P^{(i)}) - y}_2^2 
\]
NeRF is too slow for real-time rendering. Instead, for every pixel, query all 3D points from MLP. Rendering 1 pixel, you'll have 10 or 100 queries. It is nearly impossible to have real-time even with powerful GPUs. Original NeRF rendering speed is 0.06 FPS, has been improved up to 15.0 FPS (DONeRF).

\chapter{3D Gaussian splatting}
Able to dratically improve render time. Up to 135.0 FPS from NeRF's 0.071 FPS.
\section{Challenges with 3D-GS}
Significant amount of disk spaces are required in the explicit representation. Excessive Gaussian number, often millions on each scene. Next idea: for every 3D point, we are not using just RGB, we are using spherical harmonics. These coefficients requires high dimensions. Last, using \texttt{float32} is very heavy. 
\subsection{Excessive Gaussian number}
Many 3D points have small opacity. If its opacity is very small, its contribution is small, so it can be ignored. So preserve those points with high opacity, and remove those with low opacity to improve performance.  
\[
  GS_j = \sum_{i=1}^{MHW} 1(G(\mathbf{X}_j), r_i) \cdot \sigma_j \cdot \gamma_j (\Sigma),
\]
\[
  \gamma(\Sigma) = (V_{\text{norm}})^\beta 
\]
\[
  V_{\text{norm}} = \min \bp{\max{\bp{\frac{V(\Sigma)}{V_\text{max90}},1},1}}
\]
